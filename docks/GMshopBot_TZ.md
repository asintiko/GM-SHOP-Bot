# ТЗ: Telegram‑бот «GM SHOP — Guard & Contests»

**Цель:** создать бота‑модератора и помощника для магазина **GM SHOP**, который:

* защищает чат от спама/нарушений,
* красиво приветствует новых участников,
* показывает правила,
* проводит конкурсы/розыгрыши,
* ведёт карму/респекты,
* еженедельно публикует «топ активных участников» с призами,
* поддерживает «систему браков» (игровая социальная механика),
* управляется **целиком через ЛС бота** (никаких настроек в самом чате).

---

## 0) Требования к окружению и стек

* **Платформа:** Telegram Bot API.
* **Язык/Фреймворк (рекомендовано):** Python 3.10+, `aiogram 3.x` (или альтернативно `pyrogram`).
* **Хранилище:** PostgreSQL 14+ (рекомендовано) или MySQL; Redis для антифлуда/квот/очередей и задач по расписанию.
* **Планировщик задач:** APScheduler (или встроенный в фреймворк job scheduler).
* **Логи:** структурированные (JSON), уровни DEBUG/INFO/WARN/ERROR, вывод в stdout + ротация файлов.
* **Развёртывание:** Docker + docker‑compose; переменные окружения (`.env`) для токенов/ключей/ID чатов.
* **Правила приватности:** бот собирает только необходимые метаданные (см. §15).

---

## 1) Права бота в группе

Добавить бота в группу(ы) **как администратора** со следующими правами:

* удаление сообщений,
* ограничение участников (мут/бан),
* управление сообщениями (закрепление приветствия/правил — опционально),
* доступ к сообщениям (отключить «режим приватности» у бота, чтобы он видел все сообщения).

---

## 2) Роли и доступ

* **Владелец(ы):** список `OWNER_IDS` (в .env).
* **Админы магазина:** управляются через ЛС бота (панель «Админы»), хранятся в БД.
* **Модераторы:** отдельная роль с урезанными правами (мут/варн/кик, без изменения глобальных настроек).
* Все служебные действия логируются в приватный «лог‑канал» (настраиваемый `ADMIN_LOG_CHAT_ID`).

## 3) Поведение при входе пользователя (приветствие)

Срабатывает на `new_chat_members`. Бот отправляет в группу приветствие в **HTML**‑формате (шаблон редактируем через ЛС):

**Шаблон (по умолчанию):**

```html
<b>Приветствуем, <a href="tg://user?id={user_id}">{first_name}</a> 👋 в магазине «GM SHOP»!</b>

🛒 Здесь ты найдёшь <b>самый дешёвый донат</b> в игры и <b>лучший сервис</b> на рынке.
❓ По всем вопросам — сразу к администраторам <i>(первыми не пишем)</i>.
🎁 Желаем приятного отдыха и выгодных покупок!

📜 <b>Правила чата:</b> набери <code>/rules</code> — обязательно ознакомься.
```

**Опции:**

* авто‑удаление приветствия через N минут (N конфигурируется),
* опциональное закрепление сообщения с правилами (если включено).

## 4) Команда /rules — правила чата

Вызывается в группе, вывод в HTML, текст редактируем через ЛС.

**Базовая версия (улучшенная верстка):**

```html
<b>『 𝔾𝕄 𝕊ℍ𝕆ℙ 』 — ПРАВИЛА ЧАТА</b>

🚫 <b>Флуд и спам</b>: более 6 сообщений <i>подряд</i> — <b>мут на 50 минут</b>.
🚫 <b>Личные оскорбления, унижения</b> — строго запрещены.
🚫 <b>18+ контент</b> — запрещён.
🚫 <b>Флуд реакциями/стикерами/гиф</b> — ограничен (в разумных пределах).
🚫 <b>Обильная ненормативная лексика</b> — запрещена.
🚫 <b>Оскорбления администрации</b> — запрещены.
🚫 <b>Затрагивание религии</b> в оскорбительной форме — запрещено.
🚫 <b>Неадекватные стикеры</b> — запрещены.
🚫 <b>Политика</b> — вне чата (обсуждение запрещено).
🚫 <b>Заработок/ставки/казино</b> и подобные «оферы» — запрещены (автомут).

⚠️ При неадекватной реакции на мнение администрации — <b>предупреждение</b> либо <b>бан на 1 день</b> по усмотрению модератора.
🤖 При использовании развлекательных ботов — соблюдайте нормы морали. Аморальщина и спам шаблонами запрещены.

<b>UPD:</b> Правила распространяются на <b>всех</b> участников без исключений.
```

> Текст/эмодзи/оформление можно менять через ЛС -> «Правила».

## 5) Модерация: команды и автоматизация

### 5.1 Команды для админов/модераторов

Поддерживаются **оба** синтаксиса: слэш‑команды и «!»‑префикс (по желанию владельца).

* **Бан:**

  * `/ban <@user|reply|id> [время] [причина]`
  * `!бан <@user|reply|id> [время] [причина]`
  * если время не указано — бан «навсегда».
* **Мут (restrict send):**

  * `/mute <@user|reply|id> <время> [причина]`
  * `!мут ...`
* **Варн (предупреждение):**

  * `/warn <@user|reply|id> [причина]`
  * `!варн ...`
  * Порог N предупреждений → авто‑санкция (настраивается).
* **Кик:**

  * `/kick <@user|reply|id> [причина]`
  * `!кик ...`
* **Снятие санкций:**

  * `/unban <@user|id>`, `/unmute <@user|id>`, `/unwarn <@user|id> [count]`.

**Парсер времени:** `50м`, `50мин`, `50 минут`, `3ч`, `2д`, `1w`, также `1h30m`. Некорректный ввод — вежливое сообщение об ошибке.

**Ответы бота (пример):**

```html
🔒 <b>Мут</b>: <a href="tg://user?id={id}">{name}</a> — на <b>{duration}</b>.
📝 Причина: {reason}
👮 Модератор: {mod}
```

### 5.2 Антифлуд «6+ подряд»

* Логика: если один и тот же пользователь отправил ≥6 сообщений **подряд** без реплик других участников в течение окна `W` минут (по умолчанию 3), бот выдает **мут на 50 минут**.
* Параметры (`W`, длина серии, длительность мута) редактируются в ЛС.

### 5.3 Фильтры контента и автосанкции

* **Ключевые триггеры (редактируемые списки):**

  * заработок/доход без вложений, ставки, казино, 1win, mostbet, melbet, betwinner, «в личку/директ/по заработку», «подниму банк», «продам лс», «крипто‑сигналы» и т.п.
* **Действие по умолчанию:** моментальный **мут «навсегда»** (или конфигурируемая длительность), + удаление сообщения, + запись в лог.
* **Регулярные выражения** (базовый набор см. Приложение A, можно настраивать).
* **Фильтр ссылок:** опция «удалять внешние ссылки/инвайты» кроме белого списка доменов.

### 5.4 Эскалация наказаний (авто‑лесенка)

* K предупреждений (например, 3) → мут X часов.
* Повторный набор предупреждений → бан Y дней.
* Значения K/X/Y настраиваются в ЛС.

## 6) Карма/«Респекты»

### 6.1 Позитивная карма

* Если пользователь A отвечает пользователю B и в тексте есть **«+», «спасибо», «спс», «thx», «ty»** и т.п. → B получает **+1** кармы.
* Защита от фарма:

  * за одного и того же B от A только **1 зачёт/`cooldown_user_to_user`** (например, раз в 12 ч),
  * нельзя начислять себе,
  * запрет «пинг‑понга» (A↔B по очереди в коротком окне — считать один раз).

### 6.2 Негативная карма

* Слова‑триггеры (редактируемые): «–», «фу», «кринж», «дизлайк» и т.п. → **–1** кармы (но если сообщение подпадает под правила об оскорблениях — срабатывают уже мод‑санкции).
* Нижний предел за сутки (например, не ниже –3, чтобы не травили).

### 6.3 Команды

* `/karma [@user]` — показать карму пользователя.
* Еженедельный топ может учитывать **бонус за карму** (вес настраивается).

## 7) Еженедельные «Топы» с призами

* Бот **с момента добавления в группу** собирает статистику активности (см. §12 Таблицы).
* Раз в неделю (день/время задаются в ЛС) публикует пост:

  * **Топ‑3** активных (по умолчанию) с местами 🥇 🥈 🥉,
  * призы/описание — редактируются в ЛС (текст + эмодзи).
* **Метрика по умолчанию (прозрачная):**

  ```
  score = messages_count
          + karma * K
          + replies_received * R
          + reactions_received * Q   (если включено; бот фиксирует реакции)
  ```

  где `K/R/Q` настраиваемы; по умолчанию учитывать: `messages_count` + `karma*2`.
* Исключения: пользователи, имевшие бан/мут > X часов в отрезке, по умолчанию в топ не попадают (настраивается).
* Пост форматируется в HTML, например:

```html
<b>ТОП недели в «GM SHOP» 🎉</b>

🥇 <a href="tg://user?id={id1}">{name1}</a> — {score1} очков
🥈 <a href="tg://user?id={id2}">{name2}</a> — {score2} очков
🥉 <a href="tg://user?id={id3}">{name3}</a> — {score3} очков

🎁 Призы недели:
1) {prize1}
2) {prize2}
3) {prize3}

<i>Стань активнее: полезные сообщения, помощь другим и уважительное общение!</i>
```

## 8) Конкурсы/розыгрыши (Giveaways)

**Управление только в ЛС бота.**

Функционал:

* создание конкурса: тип (**реакцией**, **по ключевому слову**, **по репосту** — по мере доступности API), заголовок, описание, время проведения, число победителей, требования (состоит в чате/канале, минимум N сообщений за период и т.п.).
* авто‑напоминания за `T-24h`/`T-1h`.
* завершение → выбор победителей случайно (Mersenne Twister/`secrets`), публикация поста в группе.
* защита от накрутки: игнор аккаунтов младше N дней, «нулевая» активность исключается (опционально).
* лог конкурса хранится в БД.

Команды в ЛС:

* `Новый конкурс`, `Мои конкурсы`, `Завершить`, `Переиграть`, `Удалить`.

## 9) «Система браков» (социальная механика)

Игровая фича для вовлечения:

* `/marry @user` — предложение «брака».
* `/accept` / `/decline` — принять/отклонить (действует на последнее предложение).
* `/couple` — показать свою пару/статус.
* `/divorce` — разрыв (с подтверждением).
* Анниверсари‑напоминания (опция) — поздравление в чате.
* Кулдауны: повторное предложение одному и тому же пользователю не чаще, чем раз в `X` дней.
* Бонус к карме пары (опционально): +1 раз в сутки за конструктивные ответы друг другу.
* Антиспам: нельзя предлагать брак людям в муте/бане; ограничение по возрасту аккаунта (опционально).

## 10) Панель настроек в ЛС (главный принцип)

Все настройки — <b>только в личных сообщениях с ботом</b>.
Разделы панели:

* **Приветствие** (вкл/выкл, текст, автоудаление, закрепление).
* **Правила** (редактор HTML, превью).
* **Антифлуд** (порог «6 подряд», окно, длительность мута).
* **Фильтры** (списки слов/регексы, белые списки ссылок, действие по умолчанию).
* **Карма** (триггеры, веса, кулдауны, пределы).
* **Топ недели** (дата/время, формула, призы, критерии исключения).
* **Конкурсы** (мастер создания, выбор поста анонса).
* **Браки** (вкл/выкл, кулдауны, поздравления).
* **Роли** (добавить/удалить админов/модераторов).
* **Логи** (куда слать, уровень детализации).
* **Резервное копирование** (экспорт/импорт настроек JSON).
* **Безопасность** (блок лист id, лимиты API).
* **Мульти‑чат** (если бот в нескольких группах — отдельный профиль настроек на чат).

UI: инлайн‑кнопки + state‑машина (`aiogram` FSM), превью сообщений перед сохранением.

## 12) Модель данных (PostgreSQL — ориентир)

```sql
-- Чаты
CREATE TABLE chats (
  chat_id BIGINT PRIMARY KEY,
  title TEXT,
  settings JSONB NOT NULL DEFAULT '{}',  -- все переключатели/пороговые значения
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Пользователи
CREATE TABLE users (
  user_id BIGINT PRIMARY KEY,
  first_name TEXT,
  last_name TEXT,
  username TEXT,
  is_bot BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Членство в чате (локальная статистика)
CREATE TABLE chat_members (
  chat_id BIGINT,
  user_id BIGINT,
  joined_at TIMESTAMPTZ,
  karma INTEGER DEFAULT 0,
  messages_week INTEGER DEFAULT 0,
  replies_received_week INTEGER DEFAULT 0,
  reactions_received_week INTEGER DEFAULT 0,
  PRIMARY KEY (chat_id, user_id)
);

-- Санкции/История
CREATE TABLE sanctions (
  id BIGSERIAL PRIMARY KEY,
  chat_id BIGINT,
  target_user_id BIGINT,
  moderator_id BIGINT,
  type TEXT CHECK (type IN ('warn','mute','ban','kick','unmute','unban')),
  reason TEXT,
  duration_seconds INTEGER,   -- null для «навсегда»
  created_at TIMESTAMPTZ DEFAULT NOW(),
  expires_at TIMESTAMPTZ
);

-- Антифлуд/последние сообщения (для серии «подряд»)
CREATE TABLE message_log (
  id BIGSERIAL PRIMARY KEY,
  chat_id BIGINT,
  user_id BIGINT,
  message_id BIGINT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX ON message_log (chat_id, created_at);

-- Карма‑события
CREATE TABLE karma_events (
  id BIGSERIAL PRIMARY KEY,
  chat_id BIGINT,
  from_user_id BIGINT,
  to_user_id BIGINT,
  delta SMALLINT,            -- +1 или -1
  reason TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX ON karma_events (chat_id, to_user_id, created_at);

-- Конкурсы
CREATE TABLE giveaways (
  id BIGSERIAL PRIMARY KEY,
  chat_id BIGINT,
  title TEXT,
  description TEXT,
  winners_count INTEGER,
  status TEXT CHECK (status IN ('scheduled','active','finished','cancelled')),
  start_at TIMESTAMPTZ,
  end_at TIMESTAMPTZ,
  rules JSONB,               -- требования/фильтры
  created_by BIGINT
);

CREATE TABLE giveaway_entries (
  id BIGSERIAL PRIMARY KEY,
  giveaway_id BIGINT REFERENCES giveaways(id) ON DELETE CASCADE,
  user_id BIGINT,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE (giveaway_id, user_id)
);

CREATE TABLE giveaway_winners (
  id BIGSERIAL PRIMARY KEY,
  giveaway_id BIGINT REFERENCES giveaways(id) ON DELETE CASCADE,
  user_id BIGINT
);

-- Браки
CREATE TABLE marriages (
  id BIGSERIAL PRIMARY KEY,
  chat_id BIGINT,
  user1 BIGINT,
  user2 BIGINT,
  married_at TIMESTAMPTZ,
  divorced_at TIMESTAMPTZ
);
CREATE UNIQUE INDEX ON marriages (chat_id, user1) WHERE divorced_at IS NULL;
CREATE UNIQUE INDEX ON marriages (chat_id, user2) WHERE divorced_at IS NULL;

-- Админ‑роли
CREATE TABLE staff (
  chat_id BIGINT,
  user_id BIGINT,
  role TEXT CHECK (role IN ('owner','admin','moderator')),
  PRIMARY KEY (chat_id, user_id)
);

-- Аудит
CREATE TABLE audit_log (
  id BIGSERIAL PRIMARY KEY,
  chat_id BIGINT,
  actor_id BIGINT,
  action TEXT,
  payload JSONB,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

## 13) Алгоритмы (кратко)

### 13.1 Серия «6 подряд»

* В кольцевом буфере хранить последние `N` сообщений комнаты (например, 50).
* При новом сообщении пользователя `u`:

  1. считаем, сколько **последних подряд** сообщений также от `u` и не старше `W` минут,
  2. если ≥ порога (6) — применить мут 50 минут, удалить последние M сообщений (опция).

### 13.2 Фильтры «заработок/казино»

* Пробег по списку регексов (см. Приложение A).
* Совпадение → удалить сообщение, выдать мут (настройка), записать санкцию, уведомить модераторов.

### 13.3 Карма

* При ответе `A -> B`:

  * если найден триггер из позитивного списка и нет кулдауна — `karma[B] += 1`.
  * аналогично для негативного.
* Кулдауны и лимиты проверять по таблице `karma_events`.

### 13.4 Топ недели

* Крон‑джоб раз в неделю:

  * вычислить `score` для каждого `user` за последнюю неделю,
  * исключить нарушителей по правилам,
  * отсортировать, взять Топ‑3,
  * опубликовать пост, обнулить недельные счётчики, сохранить сводку в `audit_log`.

## 16) Нефункциональные требования

* Отзывчивость команд < 1 сек при нормальной нагрузке.

## 17) Тест‑план (основные кейсы)

1. Приветствие нового участника — корректная подстановка имени/ссылки, автоудаление.
2. `/rules` — рендер HTML, ссылки/эмодзи.
3. Антифлуд: 6 сообщений подряд → мут 50 мин, запись санкции.
4. Фильтр «казино/заработок»: удаление + мут «навсегда».
5. Мод‑команды:

   * `/ban @user 1д причина` — бан и авторазбан по таймеру.
   * `/mute @user 50м` — ограничение отправки, истечение.
   * `/warn` ×3 → авто‑мут.
6. Карма: «спасибо» в ответе → +1, кулдаун соблюдается.
7. Топ недели: пост с Топ‑3, правильные очки, сброс недельных счётчиков.
8. Конкурс: создание в ЛС → набор участников → честный выбор победителей.
9. Браки: `/marry` → `/accept` → `/couple`, кулдауны и запреты.
10. Права: модератор не может менять глобальные настройки, админ — может.
