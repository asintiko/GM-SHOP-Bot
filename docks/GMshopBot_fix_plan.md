# План фиксов GM SHOP Bot (guard + contests)

## TL;DR (приоритеты)

1. **Починить кнопку «Настройка чата»** (deep‑link в ЛС + FSM‑панель на конкретный чат, ACL).
2. **Доработать «Правила» и «Приветствие»** (редактор в ЛС, предпросмотр, плейсхолдеры, автоудаление/закреп).
3. **Добавить «/help» для юзеров** (возможности бота + краткие примеры команд; алиас `!команды`).
4. **Статистика**: `!стата` / `!статистика` для пользователя; `!общстат` для чата (неделя/всё время).
5. **Репутация/Карма** и **Браки**: починить триггеры, кулдауны, хелп; карточки профиля.
6. **Конкурсы**: мастер в ЛС, напоминания T‑24h/T‑1h, итоговый пост, антинакрутка.
7. **Общее**: логи, роли, миграции, хардненинг, BotFather список команд, тест‑план.

## 1) Кнопка «Настройка чата» — не работает → починить

**Что сделать**

* В группах при нажатии на «⚙️ Настройка чата» отправлять сообщение с инлайн‑кнопкой **«Открыть ЛС»** (deep‑link):
  `https://t.me/<bot>?start=cfg_<chat_id>_<signature>`.
  Подпись `signature = HMAC_SHA256(secret, chat_id)` во избежание подмены.
* В ЛС обработать `start` с payload `cfg_<chat_id>_<signature>`:

  1. валидировать подпись;
  2. проверить права пользователя в этом чате (через `getChatMember` или таблицу `staff`);
  3. открыть FSM‑панель настроек **именно для этого чата**.
* FSM «Настройки чата»: разделы **Приветствие**, **Правила**, **Антифлуд/Фильтры**, **Карма**, **Топ недели**, **Конкурсы**, **Браки**, **Роли**, **Логи**.
* Все сохранения — в `chats.settings` (JSONB) и/или профильные таблицы.

**Definition of Done**

* Из группы кнопка ведёт в ЛС; в ЛС открывается меню именно выбранного чата.
* Нельзя открыть настройки чужого чата без админ‑прав.
* Ошибки/отказы логируются в `ADMIN_LOG_CHAT_ID`.

**Тест‑кейсы**

* Пользователь без прав жмёт «Настройка чата» → в ЛС: «Недостаточно прав».
* Админ жмёт → открывается меню; изменения сохраняются; применяются в группе.

## 2) «Правила» и «Приветствие» — довести до продакшна

**Что сделать**

* В ЛС: экран **Правила**

  * Показ текущего текста; кнопки: «✏️ Изменить», «👁 Предпросмотр», «💾 Сохранить», «↩️ Сброс к дефолту».
  * Валидация HTML (допускаем `b/i/u/code/a`).
  * Команда в группе `/rules` выводит актуальный шаблон.
* В ЛС: экран **Приветствие**

  * Текст с плейсхолдерами: `{user_id}`, `{first_name}`, `{username}`, `{chat_title}`, `{rules_cmd}`.
  * Опции: включить/выключить, автоудаление через N минут, «закрепить правила после приветствия» (если включено — бот закрепляет пост с правилами).
* Триггер `new_chat_members` → отправка приветствия по шаблону + опциональная кнопка **/rules**.

**Definition of Done**

* В ЛС редактируются тексты, корректно подставляются плейсхолдеры.
* `/rules` в группе показывает актуальные правила.
* Приветствие работает, автоудаляется при включённой опции.

**Тест‑кейсы**

* Плохой HTML → вежливое сообщение «ошибка разметки»; сохранение блокируется.
* Новый участник → приветствие с кликабельным упоминанием и кнопкой «Правила».

## 3) Команда «возможности бота» для обычных юзеров + обновить приветствия

**Что сделать**

* Новая команда: `/help` (алиасы: `!команды`, `!help`) — динамический список по роли (User/Mod/Admin).
* Разделы `/help`:

  * **Общее**: `/rules`, `/profile`, `/karma`, `/top`, `!стата`, `!общстат`, `/marry /accept /decline /divorce /couple`.
  * **Модерация** (если права): `/ban /mute /warn /kick /unban /unmute`.
  * **Конкурсы** (если права): создание/управление через ЛС.
* Обновить дефолтное приветствие: внизу строка «Набери /help — все команды бота».

**Definition of Done**

* `/help` в группе и ЛС работает, показывает релевантные команды по роли.
* Форматирование аккуратное (HTML), примеры команд краткие.

**Тест‑кейсы**

* Обычный участник → не видит админ‑команды.
* Модератор/Админ → видит свои разделы.

## 4) Статистика для пользователей и общая по чату

**Команды**

* `!стата` / `!статистика [@user|reply|id]` — карточка пользователя (если без аргументов — для себя).
* `!общстат` — агрегированная по чату (неделя + всё время).

**Карточка пользователя (пример)**

```
📊 Статистика — {display_name}
Сообщений: 7д — {msg_7d}, всего — {msg_all}
Карма: {karma} (сегодня: {karma_today})
Предупреждений: 7д — {warn_7d}, всего — {warn_all}
Мутов/Банов: 7д — {mutes_7d}/{bans_7d}
Семейный статус: {couple|single}, браков всего: {marriages_all}, текущий с {married_at}
Розыгрыши: побед — {gw_wins}, участие — {gw_entries}
Место в последнем ТОПе: {rank_or_dash}
```

**Общая статистика (пример)**

```
🧮 Общая статистика — «{chat_title}»
Участников: {members}
Сообщений: 24ч — {msg_24h}, 7д — {msg_7d}
Топ-3 по сообщениям (7д): 1) @a — 123  2) @b — 98  3) @c — 76
Топ по карме (7д): @x — +15, @y — +12
Пар в браках: сейчас — {couples_now}, всего создано — {couples_all}
```

**Хранилище и вычисления**

* Инкрементировать счётчики при каждом сообщении/санкции (см. миграции ниже).
* Еженедельный джоб обнуляет «недельные» счётчики (или ведём скользящим окном по timestamp — на выбор).

**Миграции (минимум)**

```sql
ALTER TABLE chat_members ADD COLUMN messages_all_time INTEGER NOT NULL DEFAULT 0;
ALTER TABLE chat_members ADD COLUMN last_message_at TIMESTAMPTZ;
-- Опционально, если нужен быстрый доступ:
ALTER TABLE chat_members ADD COLUMN warnings_all_time INTEGER NOT NULL DEFAULT 0;
ALTER TABLE chat_members ADD COLUMN mutes_all_time INTEGER NOT NULL DEFAULT 0;
ALTER TABLE chat_members ADD COLUMN bans_all_time INTEGER NOT NULL DEFAULT 0;
-- Вычисляемые "за 7д" можно получать запросами по sanctions/message_log, либо поддерживать weekly-слоты в settings.
```

**Definition of Done**

* Команды возвращают карточки ≤ 1 сек, корректны для @user/реплая/ID.
* Нет утечек приватных данных; формат единообразный.

**Тест‑кейсы**

* Новичок без данных → аккуратные нули/прочерки.
* Пользователь с браком → корректная дата/пара.
* Большие чаты → запросы не падают (индексы на `message_log`, `sanctions`).

## 5) Репутация (карма/респекты) и Браки — исправить/улучшить + помощь

**Репутация**

* Починить триггеры: ответ A→B содержащий `+`, `спасибо`, `спс`, `thx`, `ty` → **+1** B (кулдаун A→B, напр. 12 ч).
* Негатив: `-`, `фу`, `кринж`, `дизлайк` → **–1** (лимит по суткам, напр. не ниже –3).
* Исключения: не учитывать сообщения, удалённые фильтром/модерацией; запрещено начислять себе; пинг‑понг‑защита.
* Команда `/karma [@user]` — показать карму; в `/profile` включить карму.

**Браки**

* Проверить и довести флоу `/marry @user` → `/accept|/decline` → `/couple` → `/divorce`.
* Ограничения: нельзя предлагать в муте/бане, кулдаун между повторами, возраст TG‑аккаунта (опция).
* Напоминание годовщин (опция).

**Помощь для участников**

* В `/help` раздел «❤️ Репутация и 💍 Браки» с краткими правилами и примерами.
* На неизвестную команду в группе — подсказка «/help».

**Definition of Done**

* Карма меняется от валидных триггеров; кулдауны соблюдаются; браки работают без коллизий.
* `/profile` показывает: дата входа в чат, сообщения (7д/всего), карма, семейный статус.

**Тест‑кейсы**

* A благодарит B 2 раза подряд → засчитывается 1 раз (кулдаун).
* A и B благодарят друг друга быстро → засчитывается один раз (антипинг‑понг).
* Предложение брака пользователю в муте → отказ с причиной.

## 6) Конкурсы/розыгрыши — оповещения и мастер в ЛС

**Что сделать**

* В ЛС: «Новый конкурс» → мастер: заголовок, описание, время, число победителей, требования (состоит в чате, ≥N сообщений за 7д и т.п.).
* Анонс в группе: пост с кнопкой «Участвую». Участие фиксируется по нажатию (CallbackQuery) или по ключевому слову (если выбран этот режим).
* **Напоминания**: автоматом за `T-24h` и `T-1h`.
* Завершение: выбор победителей через `secrets.choice`, публикация итога, запись в БД.
* Антинакрутка: игнор аккаунтов моложе N дней, «нулевая» активность исключается (если включено).
* Логи: кто создал, когда, список участников/победителей.

**Definition of Done**

* Создать → анонс → напоминания → завершение → итоговый пост — всё без ручного вмешательства.
* Нельзя участвовать дважды; кнопка/ключевое слово не учитываются повторно.

**Тест‑кейсы**

* Конкурс на 2 победителя при 1 участнике → 1 победитель, второй слот пуст не заполняется фейком.
* Участник покинул чат — по настройке либо исключается при подведении итогов, либо остаётся (настройка работает).

## 7) Общее: довести, продумать, укрепить

**Роли/ACL**

* Использовать `staff` + проверку статуса в чате. Все админ‑команды — только при наличии прав.
* Лог‑канал для всех мод‑действий и ошибок.

**Логи/Алерты**

* Структурированные JSON‑логи; на ERROR — отправка в `ADMIN_LOG_CHAT_ID` (краткое описание + stack id).
* Метрики (если подключен Prometheus) — счетчики сообщений, санкций, ошибок.

**Производительность**

* Индексы: `message_log (chat_id, created_at)`, `sanctions (chat_id, target_user_id, created_at)`, `karma_events (chat_id, to_user_id, created_at)`.
* Батч‑запись логов сообщений (bulk insert) при пиковых нагрузках.

**BotFather — список команд**

```
start - Начать
help - Возможности и команды
rules - Правила чата
profile - Профиль
karma - Карма
top - Топ недели
marry - Предложение "брака"
accept - Принять "брак"
decline - Отклонить "брак"
divorce - Разрыв "брака"
couple - Пара/статус
```

(Мод‑команды без регистрации у BotFather, либо добавить в «админский» набор.)

**Миграции — сводка**

```sql
-- см. §4; плюс для браков и конкурсов при необходимости:
-- (если не было раньше)
CREATE TABLE IF NOT EXISTS giveaway_notifications (
  id BIGSERIAL PRIMARY KEY,
  giveaway_id BIGINT REFERENCES giveaways(id) ON DELETE CASCADE,
  kind TEXT CHECK (kind IN ('T-24h','T-1h','finish')),
  sent_at TIMESTAMPTZ
);
CREATE INDEX IF NOT EXISTS ON sanctions (chat_id, target_user_id, created_at);
CREATE INDEX IF NOT EXISTS ON karma_events (chat_id, to_user_id, created_at);
```

**UX/Тексты — дефолты**

* Приветствие: см. предыдущее ТЗ; добавить строку «📜 Правила: /rules | ❓ Помощь: /help».
* `/help` — коротко, без перегруза, с примерами.

**Безопасность**

* Deep‑link payload с подписью (HMAC); проверки ролей на каждый критичный action.
* Санитизация HTML; rate‑limit на команды от одного юзера (Redis).
* Экспорт/удаление данных по запросу владельца (через ЛС).
